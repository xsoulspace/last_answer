# oka publish-target adoption (ADR-0014/0015)

Last Answer declares its store publish targets in the composition root
(`tool/oka_pipeline.dart`) — the single source of truth, including the
one-time human setup walkthroughs as dartdoc.

## Declared targets

- `playPublishTarget` — Google Play, `internal` track, `dev.xsoulspace.lastanswer`, dry-run default. Credential: service-account JSON by path (`OKA_PLAY_SERVICE_ACCOUNT_JSON` env var → well-known `~/.oka/credentials/play/service-account-json` → typed path).
- `huaweiPublishTarget` — AppGallery Connect, `beta` track, GMS-free `HuaweiBuildVariant` reusing the same `AndroidBuild`/`PipelineOverrides` consts (the oka composition declares no GMS coordinates, so `excludedGmsDeps` is empty and the same GMS-free AAB serves both stores). Credential: AGC API-client JSON by path (`OKA_HUAWEI_AGCONNECT_CREDENTIALS` env var — the name derived from the `huawei/agconnect-credentials` CredentialRef; the brief's guessed `OKA_HUAWEI_AGCREDENTIALS` is NOT the real one).

## Human setup (SSOT: the dartdoc in tool/oka_pipeline.dart)

Play: create a GCP service account (enable Google Play Android Developer API) → invite its email in Play Console → Users and permissions (Release to testing) → download the JSON key → store outside the repo or gitignored → `export OKA_PLAY_SERVICE_ACCOUNT_JSON=/path/to.json` → `oka run publish-play` (dry-run, credential-free) → `oka build aab --release` → flip `dryRun: false` here → `oka run publish-play --release --aab`.

Huawei: AppGallery Connect account → My apps → New app (Android, `dev.xsoulspace.lastanswer`), copy the numeric app id into `release: appId:` → Users and permissions → API client → store `{"client_id", "client_secret"}` JSON outside the repo → `export OKA_HUAWEI_AGCONNECT_CREDENTIALS=/path/to.json` → create `promo/store/whatsnew-en.txt` + `promo/store/whatsnew-ru.txt` → `oka run publish-huawei` (dry-run) → `oka build aab --release` → flip `dryRun: false` → `oka run publish-huawei --release --aab`.

On failure oka names every credential candidate tried (typed path → env var → well-known location) and the fix; a malformed service-account JSON names the missing fields, never values (exercised by oka_play/oka_huawei conformance tests).

## oka gaps found (reported, not worked around)

1. **`oka run <target>` is silent on dry-run success.** The plan produced by `PublishPlanStep` goes into `StepResult` data, but `okaRun`'s dispatch only prints `apk_path` — `Pipeline.run` drops all other step data. The ADR-0014 law says the dry-run "must … print exactly what a real run would do"; today the plan is only reachable via tooling. Suggested fix (oka side): print `PublishPlan.describeLines()` in `okaRun` when a `publish-plan` artifact is in state.
2. **AAB path mismatch for real runs.** `StageAabStep`/`HuaweiStageAabStep` fall back to `<buildDir>/app-release.aab`, but the oka AAB build writes `<buildDir>/aab/app-<mode>.aab` (`toolchain.dart`, `packageAndSignAab`). A standalone `oka run publish-play --release --aab` after `oka build aab --release` would target a path that does not exist. The real upload needs the fallback corrected (or an explicit artifact-path override) in oka_play/oka_huawei — not an app-side workaround.

Environment note (transient, not a gap): while the parallel `oka-h02-hotreload` agent was mid-edit in `../oka`, the oka workspace did not compile, which blocked this app's entrypoint; it resolved once that agent's edits settled. The two Dart SDKs on this machine (stable on PATH vs fvm beta) thrash the native-assets hooks cache — verification used the PATH (stable) SDK consistently, matching what the `oka` CLI invokes.
