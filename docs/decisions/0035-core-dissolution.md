# ADR 0035: Dissolving packages/core

Date: 2026-11-20
Status: accepted
Deciders: owner (directed the dissolution), steward-executed
Supersedes: the `packages/core` layer of ADR 0002's package map

## Context

`packages/core` ("Unified data layer & tools") accreted four distinct
concerns behind one barrel: the app's data layer (models, data sources,
repositories, state notifiers), the composition root (`state_di` —
GlobalStatesProvider/Initializer), the theme/asset facility (design tokens,
fonts, flutter_gen assets), and misc utilities. The composition root imported
`package:lastanswer/…` (agents, journal, entitlement, workspaces) while the
app depended on the package — a package cycle wearing the pending
world→journal inversion's face. The owner directed: remove `packages/core`,
landing each piece where the folder grammar says it belongs.

## Decision

Redistribution table (all moves via `git mv`; package names inside pubspecs
unchanged):

| core piece | new home |
| --- | --- |
| `state_di/` GlobalStatesProvider/Initializer, services/services initializers, path_utils→foundation | `lib/ui_root/` (composition root; the core→lastanswer inversion dissolves — ui_root sits at the top of the layer stack) |
| Project/Save models, projects+tags sources/repos, projects+opened+tags+paged notifiers, idea questions, Hive/Isar migration+parsers | `lib/data_projects/` |
| User/UserSettings models, locales, user+auth+dictionary sources, user repo, user notifier, auth providers | `lib/data_user/` |
| purchases/ads sources+repos+notifiers, monetization wiring | `lib/data_monetization/` |
| emoji sources+repo+notifier | `lib/data_emoji/` |
| notification model+source+repo+notifier | `lib/data_notifications/` |
| app status notifier | `lib/ui_root/` |
| theme (tokens, MaterialTheme, text styles, theme definder) | `lib/ui_root/theme/` |
| foundation extensions/utils, envs, router paths, share/file services, map-state base, generic local-db contracts | `lib/foundation/` (facility folder) |
| doc body storage | `lib/data_projects/` (project-domain helpers) |
| auth sign-in buttons | `lib/ui_settings/widgets/` (UI) |
| assets/, google_fonts/, flutter_gen output | app root: `assets/`, `google_fonts/`, `lib/foundation/generated/` (regenerated by `flutter_gen_runner` via `just gen`) |
| core's tests | `test/foundation/`, `test/data_projects/` |
| mocks (dead), dead barrels | deleted |

Consequences carried in the same decision:

- `common_imports.dart` re-exports the seven new barrels, so the ~90 former
  `package:core/core.dart` callers keep one import; direct callers now use
  per-folder barrels.
- The 12 pub deps core carried that the root lacked moved to the root
  pubspec; `core:` is gone. `core_server_client`'s vestigial `core:` dep is
  gone (it never imported core).
- The local-user/remote-user initializers moved to `ui_root` (composition
  wiring); `UserNotifier.onLoad` now takes an `onLocalUserLoad` callback
  instead of a ui_root type — no data→ui dependency.
- Wire-level law: `LocalDbVersion`, model JSON shapes and the
  `shared_preferences` keys are unchanged — this is a placement refactor,
  zero data migration.

## Consequences

- The layer stack is now `headless_core → la_locale/la_ui_kit/foundation →
  data_* backend (incl. data_journal/ecs_world/ui_chat/ecs_plugins/data_agents)
  → ui_* → ui_root`; imports point down only. The one-time core→app cycle is
  structurally impossible.
- `packages/` is purely app-support again; `shared_models` stayed at the
  time (the server depended on it) and dissolved in ADR 0038
  (`packages/server_contracts` now carries the RPC boundary).
- flutter_gen asset paths changed from `packages/core/assets/...` to app-root
  paths; `Assets.*` consumers are source-compatible, the generated file is
  regenerated.
- Known follow-up (unchanged): `data_projects/projects_repository.dart`
  imports `ui_settings/features/storage_backends_state.dart` — a data→ui
  edge to invert behind an interface (tracked separately from this ADR's
  placement work).

## Falsifiers

If new cross-concern code starts reaching into multiple `data_*` barrels
through `common_imports` instead of the folder it belongs to, the concern
split is wrong — compress or re-cut. If `ui_root` grows past composition
into domain logic, the root is becoming a new core.
