# Workbench trial guide

This is an implementation checkpoint. Use the explicit sample article first.
Production entry is Home → Workbench or a document → Workbench. The isolated
LastAnswerWorkbenchCandidate uses separate filesystem storage and disables actor
investigation because it does not include the ordinary app's host providers.

## Article

1. Open sample article. Click a paragraph, then Inspect.
2. Move down. Compare the staged proposal with the current text. Adopt, then Undo.
3. Select a heading and choose a different section destination. Stage and reject.
4. Place the text cursor within a paragraph; split there, adopt, then undo.
5. Attach a source URL to the selected claim, choosing support, contradiction or
   unresolved. This records the relationship; it does not verify the source.
6. In the ordinary app, open scoped investigation. Only the selected block enters
   the added workbench tools. A returned rewrite stays a suggestion until adopted.

## Opening and layout

1. Open Project opening connection. Select the restoration step and its destination,
   or drag the explicit restoration handle. Finish to stage; Escape cancels.
2. Compare/adopt a restoration change. Leave and Reopen; inspect recorded events.
3. Change reading width using its handle or accessible control. Adopt separately.
4. Move between document, spatial and runtime projections. Check retained selection.
5. Quit and reopen the same app. Check proposals/history and work position. If an
   anchor was removed or content changed, expect an explicit incomplete-restoration
   report rather than a claim of exact recovery.

Record the configuration, actions, expected effect and observed effect. Current
replay shows recorded workbench events; it is not yet a full independently executed
candidate runtime. Physical Vosges and touch qualification remain pending.
