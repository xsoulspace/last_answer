> The development-only launch define described below is historical. The current
> setup path is the [ordinary-launch preparation entry](ordinary-preparation.md);

This candidate projects the harness's existing installed `meaning_span_change`
action into the Last Answer document. The host owns native parsing, observed
meaning reads, executed preview, exact issued consent, materialization, checks,
file locks and DFP inverse recovery. Last Answer retains its existing backend
and invokes `HarnessAgentTools` join/orient/task admission/actions/tool_action;
it never accesses the mutable World or writes source itself.

The optional development launch binding is
`--dart-define=MEANING_GREETING_WORKSPACE=<absolute greeting fixture workspace>`.
Open an agent document and bind that same workspace. The corresponding host
factory installs only for that exact canonical directory and resolves the real
`greeting` declaration by native MeaningIndex and MeaningProps.file. The suffix
is fixed at ` — updated`; ordinary notes acquire no required experiment UI.
Explicit injected HarnessHostConfig.extraToolsWithContext also supports the
same fixture factory. Desktop process availability is required; web/mobile
return an unavailable installed-tool refusal. Only the macOS lane is measured.

UI keys `coding_agent.meaning.preview`, `.apply`, `.rollback`, `.finalize`,
`.status` and `agent_meaning_change` use the same session-bound product action.
`agent_doc_state.meaning` is the display projection. The pending permission
keeps existing reject-first controls and shows the exact ACP request summary;
the latest typed host review update is displayed only when its session,
proposal identity and effect digest match that pending request. Display packets
never restore proposal or consent authority.
