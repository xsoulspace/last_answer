# ADR 0016 — Reversible code candidates over native owners

- Status: Accepted direction; product and real-agent acceptance remain gated
- Date: 2026-10-13
- Amends: ADR 0015 coding projections; preserves its document ownership
- Parent: harness ADR 0091, semantic/conventional authoring and shared promotion

## Context and decision

The operator authorized full implementation of reusable materialization tooling,
useful local decision-model coding and seamless external-agent collaboration.
The existing greeting experiment proves a bounded workflow, not ordinary coding.

Use the existing editable workbench as the complete interaction: select work,
request a change, inspect candidate consequences, consent, Apply, Undo and reapply.
Semantic operations and conventional source candidates use the same installed
host actions and native recovery. A model may author source without a matching
semantic opcode; that does not let it bypass revision, scope or verification.

Last Answer's host adapter admits the human as a participant and invokes the
authorized action through the existing world pump. UI state and serialized
receipts do not confer authority. Keep `meaningAction` compatibility; a separate
`conventionalAction` names the conventional domain without introducing another
executor, consent ledger or history store.

DocumentRepository continues to own article operations. Source candidates refer
to the existing workspace/native transaction owner; document adoption is not
filesystem promotion. Codemap's Rust surface remains the source-analysis and
transformation owner. Vosges supplies existing input to product actions, without
embedding a second recognizer or source writer in Last Answer.

Local provider readiness, declared capability and measured coding ability are
distinct. Finite-choice models can use grounded operations and delegation;
arbitrary source authoring requires a compatible generative route. External ACP
capabilities must match bound authorized handlers, and persistent conversations
must retain their identity without replaying an unknown mutation on reconnect.

## Alternatives and consequences

A separate coding experiment screen would duplicate interaction and history.
Changing every runtime to unrestricted conventional filesystem tools would bypass
the candidate workflow. Reusing the existing projections and authority costs
adapter and rendering work, but preserves recoverable, inspectable changes.

Automatic preparation belongs in the app. The operator must not run terminal
setup or change settings to make the normal workflow available. Required platform
consent and provider authentication remain explicit product interactions.

## Acceptance

The implemented host adapter and component tests are integration evidence only.
Completion requires real local coding, an external-agent handoff, rendered
workbench Preview/Apply/Undo/reapply, exact restoration, stale/denied/failed/
unknown controls, and the existing clean-profile and release criteria. Keep the
operator-deferred physical Vosges run separate. Record independent criteria and
failures before scored runs; do not infer acceptance from a menu or health check.
